1. ### Задача про область видимости var

```javascript
var value = 1;

function first() {
  console.log(value);
}

function second() {
  var value = 2;
  console.log(value);
  first();
}

second();
```

Ответ: 2, 1

{% cut "Разбор, почему именно так" %}

Это классическая задача на **лексическую область видимости (lexical scoping)** — она проверяет, понимаешь ли ты, что JS определяет область видимости функции в момент её **объявления**, а не в момент **вызова**.

**Шаг 1: `second()` вызывается**
Внутри неё через `var value = 2` создаётся **локальная** переменная `value`, которая существует только в скоупе `second`.

**Шаг 2: `console.log(value)` внутри `second`**
Движок ищет `value` сначала в локальном скоупе `second` — находит там `2`. Выводится `2`.

**Шаг 3: вызывается `first()`**
Вот здесь ключевой момент. Функция `first` была объявлена **в глобальном скоупе**, а не внутри `second`. Её область видимости (замыкание) зафиксирована на момент объявления и указывает на глобальный контекст — она **понятия не имеет** про локальную `value` внутри `second`, даже несмотря на то, что вызвана изнутри `second`.

**Шаг 4: `console.log(value)` внутри `first`**
Движок ищет `value` в скоупе `first` — там переменной нет. Поднимается по цепочке областей видимости выше — в глобальный скоуп. Там `value = 1`. Выводится `1`.

{% endcut %}

### 2\. Задача про стрелочные функции как метод объекта

```javascript
const user = {
  name: "Аня",
  sayHi: function() { console.log(this.name) },
  // обычная функция — this определяется в момент ВЫЗОВА (динамически), а именно тем, ЧЕРЕЗ ЧТО функция вызвана (перед точкой)

  sayHiArrow: () => console.log(this.name)
  // стрелочная функция НЕ имеет своего this, Она берёт this из внешнего (лексического) окружения — то есть того контекста, где была ОБЪЯВЛЕНА сама стрелочная функция.
  // Здесь this = глобальный this (в модуле/strict mode это undefined, в обычном скрипте в браузере — window, где window.name === "" по умолчанию)

user.sayHi() // Аня
// Функция вызвана как user.sayHi() — то есть "через точку". this внутри функции = то, что стоит слева от точки, то есть user.

user.sayHiArrow() // undefined
// Стрелочная функция this не берёт от вызова (от user), она игнорирует "контекст вызова" полностью.
// this у неё зафиксирован лексически ещё в момент создания объекта user — это this внешнего кода (глобальный/модульный), а не user.

const hi = user.sayHi
hi() // undefined
// Мы просто скопировали ССЫЛКУ на функцию в переменную hi. Функция "оторвалась" от объекта user — связь с ним была только
// через способ вызова (user.sayHi()), а не через какое-то "запоминание" объекта.
// Теперь вызываем hi() — то есть БЕЗ точки, без объекта слева. this внутри обычной функции при таком вызове = undefined (в strict mode) или глобальный объект

user.sayHi.bind({ name: 'Boris' })() // Boris
// .bind(obj) создаёт НОВУЮ функцию, у которой this жёстко "прибит гвоздями" к переданному объекту { name: 'Boris' }, независимо от того, как её вызовут дальше.

user.sayHi.bind({ name: 'Boris' }).bind({ name: 'Peter' })() // Boris
// Правило: "bind можно применить только один раз по-настоящему"

user.sayHiArrow.bind({ name: 'Boris' })() // undefined
// bind НЕ РАБОТАЕТ на стрелочных функциях в принципе.
```

3. ### Расскажи про прототипы, в каких механизмах используется

{% cut "Ответ" %}

Prototype chain (цепочка прототипов) — это механизм в JavaScript, с помощью которого объекты могут наследовать свойства и методы друг от друга

**Где используются:**

* Наследование - Основной способ наследования в JS `Object.create(), `**`proto`**`, Object.setPrototypeOf`

* Конструкторы \+ .prototype - Классический паттерн до появления class `function User() {} + User.prototype.sayHi = ...`

* Классы (class) - Синтаксический сахар над прототипами `class User extends Person`

* Встроенные объекты - Все методы массивов, строк, чисел и т.д. лежат на прототипах `Array.prototype.map, String.prototype.slice`

* Общие методы - Чтобы не копировать методы в каждый экземпляр (экономия памяти) (Методы на prototype)

* Object.create() - Чистое прототипное наследование без конструктора `const child = Object.create(parent)`

* Проверка цепочки (instanceof, isPrototypeOf, Object.getPrototypeOf) `rabbit instanceof Object`

{% endcut %}

3. ### Написать полифил для new

```javascript
function myNew(constructor, ...args) {
  // 1. Создаём новый объект и сразу привязываем прототип
  //    Object.create делает то же самое, что и "obj.__proto__ = constructor.prototype", но это более правильный/безопасный способ
  const obj = Object.create(constructor.prototype);

  // 2. Вызываем конструктор с контекстом this = obj
  const result = constructor.apply(obj, args);

  // 3. Проверяем, что вернул конструктор.
  //    Если это объект (или функция) — возвращаем его, иначе возвращаем созданный объект obj
  return (result !== null && typeof result === 'object') || typeof result === 'function'
    ? result
    : obj;
}

// Проверка
function Person(name, age) {
  this.name = name;
  this.age = age;
}

Person.prototype.sayHi = function () {
  console.log(`Привет, я ${this.name}, мне ${this.age}`);
};

const p1 = myNew(Person, 'Иван', 25);
p1.sayHi(); // "Привет, я Иван, мне 25"

console.log(p1 instanceof Person); // true
```

6. ### Как запустить локально написанный JS-скрипт

{% cut "Ответ" %}

##### 1\. Через Node.js (самый частый вариант в вопросе на собеседовании)

Если это обычный `.js` файл (не привязанный к браузеру/DOM):

```
node script.js
```

Требования: должен быть установлен Node.js (`node -v` — проверить версию).

Если скрипт использует ES-модули (`import/export`) — либо:

* переименовать файл в `.mjs`, либо

* добавить в `package.json`:

```
{ "type": "module" }
```

##### 2\. В браузере (если скрипт работает с DOM)

**Через HTML-файл:**

```
<!DOCTYPE html>
<html>
<body>
  <script src="script.js"></script>
</body>
</html>
```

Открыть этот `.html` в браузере (двойным кликом или через Live Server в VS Code).

**Через консоль браузера (DevTools):**

* Открыть DevTools (`F12` или `Ctrl+Shift+I` / `Cmd+Option+I`)

* Вкладка **Console**

* Вставить код и нажать `Enter`

Подойдёт для быстрой проверки небольшого кусочка кода без создания файлов.

##### 3\. Через npm-скрипт (если это часть проекта)

Если в `package.json` есть настроенные скрипты:

```
{
  "scripts": {
    "start": "node index.js"
  }
}
```

Запуск:

```
npm start
# или
npm run <имя-скрипта>
```

##### 4\. Через онлайн-песочницы (без установки чего-либо)

Если нужно быстро проверить код без локальной настройки:

* **CodeSandbox**, **StackBlitz**, **JSFiddle**, **CodePen**, **RunJS**

##### Что, скорее всего, хотели услышать на собеседовании

Вопрос простой, но проверяет базовое понимание экосистемы:

* знаешь ли ты про **Node.js** как среду выполнения JS вне браузера

* понимаешь ли разницу между **скриптом для браузера** (нужен DOM, HTML, `<script>`) и **скриптом для Node** (нет DOM, зато есть `require`/`fs`/`process` и т.д.)

* знаешь про **консоль браузера** как быстрый способ проверки кода

7. ### Задача про асинхронщину, промисы и цепочку then

```javascript
console.log('start'); // 1

setTimeout(() => console.log('timeout'), 0); // 7

new Promise((resolve, reject) => {
  console.log('promise'); // 2
  reject('error');
})
// Промис только что был REJECTED. У .then() нет обработчика ошибок, поэтому этот .then() ПРОПУСКАЕТСЯ — не выполняется, ошибка "прокидывается" дальше в следующий .catch()
  .then(() => console.log('first then'))
// ловит reject. catch() ВСЕГДА обрабатывает ошибку. Так как внутри catch нет return reject/throw — промис после этого catch становится RESOLVED (успешным) со значением undefined
  .catch(() => console.log('first catch')) // 4
// ПРОПУСКАЕТСЯ — промис перед этим стал resolved (не rejected),
// а .catch() реагирует только на reject, поэтому просто прокидывает
// resolved-значение дальше без изменений
  .catch(() => console.log('second catch'))
  .then(() => console.log('third then')) // 5
  .then(() => console.log('fourth then')); // 6

console.log('finish'); // 3
```

8. ### Назови ключевое преимущество реакта

{% cut "Ответ" %}

* **Виртуальный DOM (Virtual DOM)** — React не работает напрямую с реальным DOM при каждом изменении (что дорого по производительности), а сначала строит виртуальное представление, сравнивает его с предыдущим (diffing) и применяет к реальному DOM только минимально необходимые изменения (reconciliation). Это классический "учебниковый" ответ.
* **Декларативность** — ты описываешь **что** должен показывать интерфейс в зависимости от состояния (`return <div>{state}</div>`), а не пишешь пошаговые инструкции **как** его менять (императивно, через `document.createElement`, `appendChild` и т.д.). Это делает код предсказуемее и проще для чтения/поддержки.
* **Компонентный подход** — UI разбивается на независимые, переиспользуемые кусочки (компоненты) со своим состоянием и логикой, что упрощает переиспользование кода и тестирование.
* **Однонаправленный поток данных (unidirectional data flow)** — данные идут от родителя к потомкам через props, а не как в двустороннем связывании — это делает предсказуемым, откуда пришли изменения и куда они идут.

{% endcut %}

8. ### В чем преимущество использования Redux перед useContext?

{% cut "Ответ" %}

#### 1\. Проблема лишних ре-рендеров

Это, пожалуй, **главный** практический аргумент. Когда значение в Context меняется, **все** компоненты, которые подписаны на этот Context (`useContext(MyContext)`), ре-рендерятся — даже если их интересует только маленький кусочек данных из этого контекста.

React-Redux (через `useSelector`) решает это встроенной оптимизацией: компонент подписывается не на весь стор, а на **конкретный кусок**, и ре-рендерится, только если именно этот кусок изменился (сравнение через `===` по умолчанию, либо кастомный компаратор).

```javascript
const user = useSelector((store) => store.user); // ре-рендер только если store.user изменился
```

#### 2\. DevTools и отладка

Redux DevTools — это мощный инструмент: видно весь стор, каждый экшн, можно **отменять действия назад/вперёд (time-travel debugging)**, смотреть diff состояния до/после каждого action. У Context ничего подобного из коробки нет.

#### 3\. Middleware

Redux даёт единую точку для side-эффектов и кросс-cutting логики через middleware: логирование каждого действия, асинхронная логика (`redux-thunk`, `redux-saga`), аналитика, персистентность стора (`redux-persist`) и т.д. С Context/useReducer всё это придётся городить руками.

#### 4\. Структура и предсказуемость на масштабе

Redux навязывает строгий паттерн: единый стор, чистые reducers, экшены как единственный способ изменения состояния. На маленьком проекте это оверхед, но на большом — это стандартизирует то, как разные разработчики меняют состояние, что упрощает онбординг и код-ревью.

Context же — это просто "механизм передачи данных вниз по дереву без прокидывания props", он **не** предназначен изначально быть полноценным state-менеджером, просто его для этого часто используют вместе с `useReducer`.

#### 5\. Работа вне React-дерева

Redux store существует как независимый JS-объект, к нему можно обращаться и вне React-компонентов (например, в утилитах, вне рендер-цикла). Context же принципиально завязан на React-дерево компонентов и его Provider.

#### Когда Context вполне достаточен

Стоит сказать и обратное — для многих задач Redux избыточен:

* Редко меняющиеся данные (тема оформления, локаль, авторизованный пользователь) — идеально для Context, лишние ре-рендеры некритичны.

* Небольшое приложение без сложной асинхронной логики.

* Когда не нужен time-travel debugging и сложный middleware-pipeline.

{% endcut %}

8. ### Что такое **Redux Thunk? Почему** в Reducer можно передавать только синхронный код?

{% cut "Ответ" %}

**Redux Thunk** — middleware, позволяющее диспатчить функции вместо объектов, что даёт возможность писать асинхронную логику (запросы, условные dispatch) *до* того, как в reducer попадёт финальный синхронный экшен.

Без thunk `dispatch` может принять только plain object:

```javascript
dispatch({ type: 'SET_USER', payload: user });
```

С thunk можно диспатчить функцию:

```javascript
dispatch((dispatch, getState) => {
  // тут можно делать что угодно: async/await, условия, несколько dispatch подряд
});
```

Как использовать:

```javascript
const fetchUser = (id) => {
  return async (dispatch, getState) => {
    dispatch({ type: 'FETCH_USER_START' });
    try {
      const response = await fetch(`/api/users/${id}`);
      const user = await response.json();
      dispatch({ type: 'FETCH_USER_SUCCESS', payload: user });
    } catch (error) {
      dispatch({ type: 'FETCH_USER_ERROR', payload: error.message });
    }
  };
};

// использование:
dispatch(fetchUser(123));
```

Тут одна "экшен-функция" диспатчит несколько **синхронных** экшенов в разные моменты времени — до, после успешного и после неуспешного запроса. Сам асинхронный код (запрос) живёт в thunk, а не в reducer.

**Reducer синхронный, потому что:** Redux ожидает немедленный возврат нового state, reducer должен быть чистой функцией без побочных эффектов для предсказуемости, а также это необходимо для работы time-travel debugging — вся асинхронность выносится в middleware, а не в сам reducer.

{% endcut %}

8. ### Задача про сортировку массива

```javascript
// Есть массив операций. Необходимо операции отсортировать по дате и сгруппировать их по году, а в качестве значений представить массивы c датами в формате MM-DD.
//  Пример результата:
  result = {
    "2017": [
      "07-31",
      "08-22"
    ],
    "2018": [
      "01-01"
      "02-22"
    ]
  }

const operations = [
    { "date": "2017-07-31", "amount": "5422" },
    { "date": "2017-06-30", "amount": "5220" },
    { "date": "2017-05-31", "amount": "5365" },
    { "date": "2017-08-31", "amount": "5451" },
    { "date": "2017-09-30", "amount": "5303" },
    { "date": "2018-03-31", "amount": "5654" },
    { "date": "2017-10-31", "amount": "5509" },
    { "date": "2017-12-31", "amount": "5567" },
    { "date": "2018-01-31", "amount": "5597" },
    { "date": "2017-11-30", "amount": "5359" },
    { "date": "2018-02-28", "amount": "5082" },
    { "date": "2018-04-14", "amount": "2567" }
];

// Решение
function sortOperations(operations) {
  // 1. Сортируем один раз (строки YYYY-MM-DD сортируются лексикографически корректно)
  const sorted = [...operations].sort((a, b) => a.date.localeCompare(b.date));

  // 2. Группируем за один проход
  return sorted.reduce((acc, { date }) => {
    const year = date.slice(0, 4); // выделили из строки год
    const md = date.slice(5);          // выделили из строки месяц  день

    if (!acc[year]) { // если в acc еще ничего нет по ключу year - создаем этот ключ и кладем туда пустой массив
      acc[year] = [];
    }
    acc[year].push(md); // в ином случае - по ключу year добавляем в массив месяц-день

    return acc;
  }, {});
}
```

13. ### Исправить реактовский компонент

```javascript
import React from "react"; // Хуки можно импортировать точечно
 
const PleaseReviewMe = () => {
  const [count, setCount] = React.useState(1);
  const [items, setItems] = React.useState([{ id: 1 }]);
  
// useLayoutEffect здесь не нужен, Для подписки на события достаточно обычного useEffect. 
  React.useLayoutEffect(() => {
    document.addEventListener("click", () => {
      setInterval(() => console.log(count), 1000); // В setInterval всегда логируется старое значение count.
    });
  });  // useLayoutEffect без зависимостей. Эффект выполняется на каждый рендер → бесконечное добавление слушателей
// Нет cleanup
// addEventListener никогда не снимается → утечка памяти.
// Каждый клик по документу создаёт новый setInterval, который никогда не очищается.
 
  const click = React.useCallback(() => { // стоит назвать handleClick
    setCount(count + 1); // Нужно передать коллбек с предыдущим значением setCount((prev) => prev + 1);
    setItems([...items, { id: count + 1 }]); // setItems((prev) => [...prev, { id: prev.length + 1 }]);
  } ); // useCallback без массива зависимостей + прямое использование count/items → устаревшие значения.
 
  return (
    <React.Fragment> // можно заменить на <></>
      <ul>
        {items.map((item) => (
          <li>{item.id}</li> // Отсутствует key
        ))}
      </ul>
      <button onClick={() => click()}>add one</button> // можно убрать лишнюю обертку onClick={handleClick}
    </React.Fragment>
  );
};
export default PleaseReviewMe;
```
