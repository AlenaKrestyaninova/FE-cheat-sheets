Идея. Выбираем один элемент — опорный (pivot). Разбиваем оставшийся массив на две части: те, что меньше pivot, и те, что больше. Рекурсивно сортируем каждую часть тем же способом, потом склеиваем: [меньшие] + [pivot] + [большие].

```javascript
function quickSort(arr) {
  if (arr.length <= 1) return arr; // база рекурсии

  const pivot = arr[Math.floor(arr.length / 2)]; // берём средний элемент как pivot
  const less = arr.filter(x => x < pivot);
  const equal = arr.filter(x => x === pivot);
  const greater = arr.filter(x => x > pivot);

  return [...quickSort(less), ...equal, ...quickSort(greater)];
}
```

Это упрощённая "функциональная" версия — она проще для собеса, но не in-place (тратит доп. память на новые массивы). Есть и in-place вариант через два указателя, но с ним дольше возиться, для устного объяснения хватит этого.

Почему выбор pivot важен. Если каждый раз брать, например, первый элемент, а массив уже отсортирован (или отсортирован в обратном порядке) — деление получается совсем неравномерным (одна часть пустая, вторая — почти весь массив), и рекурсия проседает по производительности. Поэтому часто берут средний элемент, случайный, или медиану — чтобы деление было более сбалансированным.

Сложность:

Средний случай: O(n log n). На каждом уровне рекурсии — проход по n элементов (filter), а глубина рекурсии — log n, потому что массив каждый раз делится примерно пополам.
Худший случай: O(n²). Если pivot каждый раз оказывается самым маленьким или самым большим элементом (неудачный выбор + неудачные данные) — деление на "пустое + почти всё" превращает log n уровней в n уровней.
Память: O(log n) для in-place версии (глубина рекурсии), но у нашей функциональной версии выше — O(n) из-за создания новых массивов на каждом уровне.

Если спросят "quicksort vs mergesort" — коротко: mergesort всегда гарантирует O(n log n) (стабильна по времени, не деградирует), но тратит O(n) доп. памяти на слияние. Quicksort в среднем чуть быстрее на практике (лучше работает с кэшем процессора), но в худшем случае может просесть до O(n²), если не повезло с pivot.
