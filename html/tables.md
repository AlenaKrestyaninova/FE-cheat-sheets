# Таблицы

### Структура таблицы

HTML-таблица строится из следующих элементов:

**Основные структурные:**

* `<table>` — корневой элемент

* `<thead>` — секция заголовков

* `<tbody>` — секция тела (основные данные)

* `<tfoot>` — секция подвала (итоги, суммы)

* `<tr>` — строка (table row)

* `<th>` — ячейка-заголовок (table header)

* `<td>` — ячейка с данными (table data)

**Дополнительные:**

* `<caption>` — подпись к таблице (важна для доступности)

* `<colgroup>` \+ `<col>` — группировка столбцов для стилизации

* `<thead>`, `<tbody>`, `<tfoot>` технически опциональны, но браузер всё равно создаёт `<tbody>` в DOM, даже если его нет в разметке

---

### Семантика секций: 

* `<thead>`Строки с заголовками столбцов
* `<tbody>`Основной массив данных. Может быть несколько в одной таблице
* `<tfoot>`Итоговые строки — суммы, средние значения

**Важно:** `<tfoot>` в HTML5 идёт после `<tbody>` в разметке, но браузер может отрисовать его внизу. В старом HTML4 `<tfoot>` шёл до `<tbody>`.

При печати страницы браузеры повторяют `<thead>` и `<tfoot>` на каждой странице — это важное практическое преимущество.

### th vs td

`<th>` используется когда ячейка является **заголовком** для других ячеек.

Ключевые отличия:

* По умолчанию браузер рендерит `<th>` жирным и по центру, но это чисто визуальное следствие, не суть

* Атрибут `scope` у `<th>` указывает, для каких ячеек этот заголовок является заголовком:

  * `scope="col"` — для всего столбца

  * `scope="row"` — для всей строки

  * `scope="colgroup"` / `scope="rowgroup"` — для группы столбцов/строк

* `<th>` создаёт связь для скринридеров: когда пользователь попадает в `<td>`, ридер зачитывает соответствующий `<th>`

```xml
<thead>
  <tr>
    <th scope="col">Имя</th>
    <th scope="col">Возраст</th>
  </tr>
</thead>
<tbody>
  <tr>
    <th scope="row">Иван</th>  <!-- заголовок строки -->
    <td>28</td>
  </tr>
</tbody>
```

### colspan и rowspan

* `colspan="N"` — ячейка занимает N **столбцов** по горизонтали

* `rowspan="N"` — ячейка занимает N **строк** по вертикали

```xml
<tr>
  <td colspan="2">Занимает 2 колонки</td>
</tr>
<tr>
  <td rowspan="3">Занимает 3 строки</td>
  <td>Обычная ячейка</td>
</tr>
```

**Частая ошибка:** когда ячейка объединена через `rowspan`, в следующих строках не нужно добавлять ячейку на то место — иначе сетка «съедет».

### Доступность таблиц (Accessibility)

Это самая богатая тема, там много нюансов.

**1. `<caption>` — обязательна для доступности** Описывает цель таблицы. Скринридер зачитывает её перед самой таблицей.

```xml
<table>
  <caption>Продажи по регионам за Q1 2025</caption>
```

**2. `scope` у `<th>`** — см. выше. Без него скринридер не знает, к чему относится заголовок.

**3. Атрибут `headers`** — для сложных таблиц с вложенными заголовками, когда `scope` недостаточно:

```
<th id="name">Имя</th>
...
<td headers="name">Иван</td>
```

**4. `role="presentation"` или `role="none"`** — используется когда таблица используется для **верстки** (layout table), а не для данных. Убирает семантику для скринридеров. Хотя сегодня так делать не следует совсем — для верстки есть Flexbox и Grid.

**5. Избегать вложенных таблиц** — крайне запутывает навигацию для скринридеров.

**6. Не использовать таблицы для вёрстки** — главное правило. Таблица = табличные данные.

**7. `summary` атрибут** — устарел в HTML5, заменён на `<caption>` \+ `aria-describedby`.

### Стилизация через colgroup

```xml
<table>
  <colgroup>
    <col style="background-color: #f0f0f0">
    <col span="2">
  </colgroup>
  ...
</table>
```

Позволяет стилизовать целый столбец без CSS-классов на каждой ячейке. Работает только с ограниченным набором CSS-свойств: `background`, `border`, `width`, `visibility`.
