# Базовая структура HTML-документа

## Минимально валидный HTML-документ

```xml
<!DOCTYPE html>
<html lang="ru">
  <head>
    <meta charset="UTF-8">
    <title>Заголовок</title>
  </head>
  <body>
    Контент
  </body>
</html>
```

Формально браузер отрендерит страницу даже без большинства этих элементов — но это будет невалидный документ с непредсказуемым поведением.

---

## `<!DOCTYPE html>`

Это **не HTML-тег** — это инструкция для браузера. Она сообщает, что документ написан по стандарту **HTML5**.

**Зачем нужен:** Браузеры имеют два режима рендеринга:

* **Standards mode (строгий)** — браузер следует современным стандартам W3C

* **Quirks mode (режим совместимости)** — браузер имитирует баги старых браузеров 90-х (IE5, Netscape) для обратной совместимости

Если `<!DOCTYPE html>` отсутствует или написан неправильно — браузер переключается в Quirks mode. В нём, например, иначе работает боксовая модель: `width` включает `padding` и `border`, что ломает вёрстку.

**Важные детали:**

* Регистр не важен: `<!DOCTYPE HTML>` и `<!doctype html>` — одно и то же

* Должен быть **первой строкой** документа, до `<html>`

* В старом HTML4 DOCTYPE был длинным и содержал ссылку на DTD: `<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01//EN" "http://www.w3.org/TR/html4/strict.dtd">` — в HTML5 его упростили до `<!DOCTYPE html>`

---

## Элемент `<html>`

Корневой элемент документа — все остальные элементы являются его потомками.

**Ключевой атрибут — `lang`:**

```
<html lang="ru">
<html lang="en-US">
```

Зачем нужен `lang`:

* Скринридеры выбирают правильное произношение и голос

* Браузер предлагает перевод страницы

* CSS-свойство `hyphens: auto` работает корректно только при заданном языке

* Поисковики учитывают язык при ранжировании

Без `lang` скринридер может читать русский текст с английским акцентом — это грубая ошибка доступности.

## Что размещается в `<head>`

### Обязательные элементы:

```xml
<meta charset="UTF-8">      <!-- кодировка, должна быть первой -->
<title>Название страницы</title>  <!-- единственный обязательный видимый снаружи элемент -->
```

### Viewport (обязателен для адаптивности):

```xml
<meta name="viewport" content="width=device-width, initial-scale=1">
```

Без него мобильный браузер рендерит страницу как десктопную (шириной \~980px) и уменьшает её.

### SEO:

```xml
<meta name="description" content="Описание страницы для поисковиков">
<meta name="robots" content="index, follow">
<link rel="canonical" href="https://example.com/page">
```

### Open Graph (соцсети):

```xml
<meta property="og:title" content="Заголовок для шаринга">
<meta property="og:image" content="https://example.com/image.jpg">
```

### Подключение ресурсов:

```xml
<link rel="stylesheet" href="styles.css">
<link rel="icon" href="favicon.ico">
<link rel="preload" href="font.woff2" as="font">   <!-- предзагрузка -->
<link rel="preconnect" href="https://fonts.googleapis.com"> <!-- ранний DNS -->
<script src="app.js" defer></script>
```

### `<base>`:

```xml
<base href="https://example.com/">
```

Устанавливает базовый URL для всех относительных ссылок на странице. Используется редко, но знать стоит.

## `<meta charset>`

```
<meta charset="UTF-8">
```

**Кодировка** — это таблица соответствия байтов и символов. Без указания кодировки браузер будет угадывать, что за символы в файле.

**Почему UTF-8:**

* Охватывает все языки мира, эмодзи, математические символы

* Совместима с ASCII (первые 128 символов идентичны)

* Стандарт де-факто для веба

**Критически важно:** `<meta charset>` должен быть в **первых 1024 байтах** документа. Браузер начинает парсить HTML до того, как загружает его целиком, и если кодировка встретится позже — браузер уже мог неправильно декодировать начало файла и перепарсит документ заново. Поэтому `<meta charset>` ставят **первым элементом** в `<head>`.

**Что будет без него:** кириллица, иероглифы и другие не-ASCII символы превратятся в «кракозябры» — если кодировка файла и предположение браузера не совпадут.

## Как браузер интерпретирует HTML-документ

Это самая глубокая часть темы. Процесс состоит из нескольких этапов:

### 1. Загрузка и парсинг (HTML Parser)

Браузер читает HTML **потоково** (не ждёт полной загрузки) и строит **DOM (Document Object Model)** — дерево объектов.

Парсер HTML **максимально толерантен к ошибкам** — это заложено в стандарт. Незакрытые теги, неправильная вложенность — браузер исправит сам по определённым правилам. Именно поэтому «сломанный» HTML всё равно отображается.

### 2. Блокирующие ресурсы

Парсинг останавливается при встрече:

* `<script>` без `async`/`defer` — браузер ждёт загрузки и выполнения скрипта (JS может изменить DOM через `document.write`)

* `<link rel="stylesheet">` — не блокирует парсинг HTML, но блокирует рендеринг

Поэтому классическая рекомендация: CSS — в `<head>`, скрипты — перед `</body>` или с `defer`.

### 3. CSSOM

Параллельно с DOM браузер строит **CSSOM (CSS Object Model)** из всех подключённых стилей.

### 4. Render Tree

DOM \+ CSSOM объединяются в **Render Tree** — дерево только видимых элементов (без `display: none`, `<head>`, `<script>` и т.д.).

### 5. Layout (Reflow)

Браузер вычисляет **размеры и позиции** каждого элемента на странице.

### 6. Paint & Composite

Элементы отрисовываются на экране. Некоторые элементы выносятся на отдельные **GPU-слои** (compositing) для оптимизации анимаций.

### Важные понятия для интервью:

* **Reflow** — пересчёт геометрии (дорогая операция), триггерится изменением размеров, позиций

* **Repaint** — перерисовка без изменения геометрии (дешевле), триггерится изменением цвета, тени

* **`defer` vs `async`**: `defer` — скрипт выполняется после парсинга HTML, в порядке появления; `async` — выполняется сразу после загрузки, порядок не гарантирован
