# Тык в браузер

### 1. **Ввод URL и разбор**

* Ты вводишь URL (например, https://example.com/path).

* Браузер разбирает URL на части:

  * **Протокол** (https).

  * **Домен** (example.com).

  * **Путь** (/path).

  * **Параметры** (если есть, например, ?id=123).

---

### 2. **Проверка кэша браузера**

* Браузер проверяет, есть ли в кэше ответ для этого URL (например, HTML, CSS, JS или изображения).

* **Типы кэшей**:

  * **Browser Cache**: Хранит ресурсы (CSS, JS, изображения) с заголовками Cache-Control, ETag или Last-Modified.

  * **DNS Cache**: Хранит соответствие домена и IP-адреса.

  * **Service Worker Cache** (если настроен): Для оффлайн-доступа или кэширования API-ответов.

* Если данные в кэше актуальны, браузер может использовать их, чтобы не отправлять запрос.

---

### 3. **DNS-разрешение (Domain Name System)**

* Если домен не в кэше, браузер отправляет запрос к DNS-серверу, чтобы преобразовать домен (example.com) в IP-адрес (например, 93.184.216.34).

* Процесс:

  1. Браузер проверяет локальный DNS-кэш (или hosts-файл).

  2. Если не находит, обращается к DNS-серверу провайдера.

  3. DNS-сервер рекурсивно ищет IP через корневые и доменные серверы.

---

### 4. **Установление соединения (TCP и TLS Handshake)**

* **TCP Handshake** **(тройное рукопожатие)**:

  * Браузер устанавливает TCP-соединение с сервером по IP-адресу.

    * SYN (synchronize) — Клиент отправляет на сервер специальный пакет SYN, уведомляя о намерении установить соединение и передавая начальный порядковый номер для передачи данных.

    * SYN-ACK (synchronize-acknowledgment) — Сервер, получив пакет SYN, отправляет ответный пакет SYN-ACK. Этот пакет подтверждает получение запроса и также содержит свой начальный номер для синхронизации.

    *  ACK (acknowledgment) — Клиент отправляет пакет ACK для подтверждения получения пакета SYN-ACK. После этого соединение считается установленным, и данные могут передаваться.

  * Это гарантирует надёжную передачу данных.

* **TLS Handshake** (если HTTPS):

  * Браузер и сервер договариваются о шифровании (протокол TLS/SSL).

  * Этапы:

    1. Клиент отправляет "Client Hello" (поддерживаемые версии TLS, шифры).

    2. Сервер отвечает "Server Hello", сертификатом и публичным ключом.

    3. Клиент проверяет сертификат (через CA — Certificate Authority).

    4. Устанавливается общий секретный ключ для шифрования.

  * После этого данные передаются в зашифрованном виде.

---

### 5. **Отправка HTTP-запроса**

* Браузер формирует HTTP-запрос (GET, POST и т.д.) и отправляет его серверу.

* Запрос включает:

  * Метод (GET, POST, etc.).

  * Заголовки (User-Agent, Accept, Authorization, etc.).

  * Тело запроса (если есть, например, для POST).

* Сервер обрабатывает запрос и возвращает ответ (например, HTML, JSON или статус-код).

---

### 6. **Получение и обработка ответа**

* Сервер возвращает HTTP-ответ с:

  * Статус-кодом (например, 200 OK, 301 Moved Permanently).

  * Заголовками (Content-Type, Cache-Control).

  * Телом ответа (HTML, CSS, JS, изображения и т.д.).

* Браузер парсит HTML (создаёт DOM — Document Object Model) и CSS (создаёт CSSOM — CSS Object Model).

---

### 7. **Рендеринг страницы**

* Браузер объединяет DOM и CSSOM в **Render Tree** (дерево рендеринга).

* Этапы:

  1. **Layout (Reflow)**: Вычисление размеров и позиций элементов.

  2. **Painting**: Отрисовка пикселей на экране.

  3. **Compositing**: Сборка слоёв для отображения (особенно важно для анимаций).

* JavaScript может запускаться синхронно (блокирует рендеринг) или асинхронно (через defer/async).

---

### 8. **Загрузка дополнительных ресурсов**

* Браузер загружает ресурсы, указанные в HTML (CSS, JS, изображения, шрифты).

* Это может вызывать дополнительные DNS-запросы, TCP/TLS-соединения и HTTP-запросы.

* **Для фронтенда**: Оптимизируй загрузку:

  * Минифицируй CSS/JS.

  * Используй ленивую загрузку (loading="lazy" для изображений).

  * Применяй preload или prefetch для критических ресурсов (\<link rel="preload"\>).

---

### 9. **Клиентская маршрутизация и SPA (если применимо)**

* Если это SPA (Single Page Application), после загрузки начального HTML JavaScript (React, Vue, etc.) берёт управление.

* Клиентский роутер обрабатывает пути в URL и загружает данные через API (асинхронно, через fetch).

---

### 10. **Кэширование ответа**

* Браузер кэширует полученные ресурсы в соответствии с заголовками Cache-Control, ETag или Expires.

* Это ускоряет последующие запросы к тем же ресурсам.
