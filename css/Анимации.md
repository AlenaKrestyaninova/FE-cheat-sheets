# Анимации

### Transition

`transition` — это плавное изменение CSS-свойства от одного значения к другому при смене состояния элемента (например, `:hover`, добавление класса через JS).

Синтаксис: `transition: property duration timing-function delay`

```css
.btn {
  background: blue;
  transition: background 0.3s ease;
}
.btn:hover {
  background: red;
}
```

Transition — это всегда реакция на событие. Он не работает сам по себе — нужен триггер.

---

### Animation vs Transition

|                    | Transition            | Animation           |
|--------------------|------------------------|----------------------|
| Триггер            | Нужен (hover, class)  | Не нужен             |
| Количество шагов   | 2 (из A в B)           | Любое (keyframes)    |
| Повторение         | Нет                    | `infinite` и др.     |
| Управление         | Ограничено             | Полное               |

`animation` работает через `@keyframes` и запускается сразу или по заданному условию. Может воспроизводиться бесконечно, реверсироваться, иметь паузы.

```css
@keyframes pulse {
  0%   { transform: scale(1); }
  50%  { transform: scale(1.1); }
  100% { transform: scale(1); }
}

.icon {
  animation: pulse 1s ease-in-out infinite;
}
```

---

### Keyframes

`@keyframes` — правило, задающее промежуточные состояния анимации. Вместо процентов можно использовать `from` / `to` (эквивалентно 0% / 100%).

```css
@keyframes slide-in {
  from { opacity: 0; transform: translateX(-50px); }
  to   { opacity: 1; transform: translateX(0); }
}
```

---

### Какие свойства анимировать эффективно

Браузер рендерит через несколько стадий: **Layout → Paint → Composite**. Чем позже стадия, тем дешевле.

* **Composite only (быстро):** `transform`, `opacity` — не вызывают ни Layout, ни Paint. GPU обрабатывает напрямую.
* **Paint (средне):** `color`, `background`, `box-shadow` — не пересчитывают геометрию, но перерисовывают пиксели.
* **Layout (дорого):** `width`, `height`, `top`, `left`, `margin`, `padding` — браузер пересчитывает геометрию всего документа.

Правило: анимируй только `transform` и `opacity`.

---

### Transform

`transform` — CSS-свойство, которое изменяет геометрию элемента без влияния на поток документа. Элемент остаётся "на месте" в DOM, но визуально трансформируется.

Основные функции:

* `translate(x, y)` / `translateX(x)` / `translateY(y)` — перемещение
* `scale(n)` / `scaleX(n)` / `scaleY(n)` — масштабирование (1 = исходный)
* `rotate(deg)` — поворот
* `skew(x, y)` — наклон

Можно комбинировать: `transform: translate(10px, 20px) scale(1.2) rotate(45deg)` — применяются справа налево.

---

### GPU-ускорение

Браузер отделяет определённые элементы на отдельный **compositing layer** и отправляет его на GPU. GPU занимается только перемещением/масштабированием уже нарисованных пикселей — это очень быстро.

Слой создаётся автоматически при использовании `transform` и `opacity` в анимациях. Можно также явно указать: `will-change: transform`.

**Почему `top/left` медленнее:** Изменение `top` или `left` означает: "элемент теперь находится в другом месте". Браузер обязан пересчитать Layout (где теперь все соседние элементы?), затем перерисовать (Paint). GPU здесь не помогает. `translate` же говорит: "нарисованный слой просто сдвинуть на экране". Layout не затрагивается. GPU делает это за одну операцию.

---

### will-change

`will-change` — подсказка браузеру о том, что свойство скоро будет анимироваться. Браузер заранее создаёт compositing layer, избегая "прыжка" при старте анимации.

```css
.card:hover {
  will-change: transform;
}
```

**Когда использовать:** только для конкретных тяжёлых анимаций, которые вызывают видимые задержки при старте.

**Почему не везде:** каждый `will-change` — это отдельный слой в памяти GPU. Злоупотребление приводит к большему потреблению памяти и может замедлить рендеринг.
