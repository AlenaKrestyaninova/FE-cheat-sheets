# Node.js, npm, package.json, .npmrc

Node.js — это среда выполнения кода JavaScript вне браузера, которая позволяет писать серверный код для веб-страниц и веб-приложений, а также для программ командной строки. С помощью платформы можно работать с файлами, сетью, базами данных и другими системными ресурсами на сервере.

##### **Где используется Node.js** \{#где-используется-nodejs\}

- Создание серверных приложений - для создания веб-серверов, API, приложений реального времени, других серверных приложений, SSR для React и других фронтенд-фреймворков.

- Веб-разработка - можно создавать полноценные веб-приложения, работать с базами данных, управлять маршрутизацией и обработкой запросов от клиентов. Подходит для разработки Real Time Applications — веб-приложений, реагирующих на действия пользователя в режиме реального времени (Google Docs)

- Потоковая передача данных -  полезно для разработки систем обработки потоков данных, стримингового видео, чатов и других приложений, требующих эффективной передачи данных.

- Инструменты разработки - используется для создания сборщиков модулей, сред разработки, средств автоматизации задач (например, сборки проекта, запуска тестов) и других инструментов, упрощающих разработку и работу с JavaScript-кодом.

- Интернет вещей (IoT) - предоставляет возможности для связи с устройствами, обработки данных с датчиков, управления и мониторинга устройств, а также интеграции с облачными сервисами.

- Командная строка - для создания командных инструментов и скриптов на сервере. Предоставляет доступ к системным ресурсам и позволяет автоматизировать задачи в командной строке.

- Микросервисная архитектура - где отдельные компоненты системы могут быть реализованы как отдельные сервисы, взаимодействующие друг с другом через API.

### **Файл package.json**

\-содержит в себе информацию о вашем приложении: название, версия, зависимости и тому подобное. Любая директория, в которой есть этот файл, интерпретируется как Node.js-пакет, даже если вы не собираетесь публиковать его.
Секции:

**1. scripts:**

* определяет команды, которые можно запускать через npm run \<script-name\>.

* Запуск: npm start, npm run build, npm test (start и test — встроенные команды, их можно вызывать без run)

* Можно создавать кастомные скрипты для автоматизации задач (сборка, тесты, деплой).

  ```
  "scripts": {
    "start": "node index.js",
    "build": "webpack",
    "test": "jest"
  }
  ```

**2. dependencies vs devDependencies:**

* **dependencies** — для работы приложения:

  * Пакеты, необходимые для работы приложения в продакшене (например, express, react).

  * Устанавливаются с npm install \<package\> --save (или просто npm install \<package\>).

  * Пример: "dependencies": \{ "express": "\^4.17.1" \}.

  * Эти пакеты нужны для работы приложения в боевом режиме.

* **devDependencies** — для разработки, тестирования, сборки:

  * Пакеты, используемые только во время разработки или тестирования (например, jest, webpack, eslint).

  * Устанавливаются с npm install \<package\> --save-dev.

  * Пример: "devDependencies": \{ "jest": "\^29.0.0" \}.

  * Не включаются в продакшен-сборку (например, при npm install --production).

### **Пакеты в Node.js**

\-один или несколькоJavaScript-файлов, представляющих собой какую-то библиотеку или инструмент.
***npm (аббр. node package manager)*** — это стандартный менеджер пакетов, автоматически устанавливающийся вместе с Node.js. Он используется для скачивания пакетов из облачного сервера npm, либо для загрузки пакетов на эти сервера.

**1. Установка пакетов:**

* npm install \<package\> — устанавливает пакет локально в проект (в node\_modules).

* npm install \<package\> -g — глобальная установка (для CLI-утилит, например).

* npm install \<package\>@\<version\> — установка конкретной версии пакета.

* npm install — устанавливает все зависимости из package.json.

**2. Версионирование:**

* В package.json указываются зависимости с версиями, например: "express": "\^4.17.1".

  * \^ — разрешает минорные и патч-обновления (4.x.x).

  * \~ — только патч-обновления (4.17.x).

  * Точная версия: "4.17.1".

* npm outdated — показывает устаревшие пакеты.

* npm update — обновляет пакеты в рамках указанных версий.

**3. Lock-файлы:**

* package-lock.json (или npm-shrinkwrap.json) фиксирует точные версии всех установленных пакетов и их зависимостей.

* Гарантирует одинаковую установку зависимостей на разных машинах.

* Генерируется автоматически при npm install, обновляется при добавлении/удалении пакетов.

* Хранит дерево зависимостей и ссылки на их источники (репозитории, хэши).

### .npmrc

Файл .npmrc (или глобальный \~/.npmrc) задаёт настройки для npm, такие как реестры, авторизация, прокси и т.д.

Может быть:

* **Локальным** (в корне проекта, влияет только на проект).

* **Глобальным** (в домашней папке пользователя, например, \~/.npmrc).

* **Встроенным** (в npm по умолчанию).

Команды:

* Получить помощь по настройке программы «npm» : *npm help config*

* Просмотреть текущие настройки (заданные пользователем): *npm config list*

* Посмотреть прям все настройки: *npm config list -long*

* Задать проекту имя автора: *npm config set init.author.name "Alenochka"*

* Использовать с npm собственный реестр модулей: *npm config set registry "https://my-custom-registry.registry.nodesource.io/"*

* Изменить программу для командной строки: *npm config set script-shell="powershell"*

* Указать, что должно выводиться в консоль после npm install: *npm config set loglevel="silly"* или *npm config set loglevel="silent"*
