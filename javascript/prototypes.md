# Прототипы

У каждого объекта в JS есть скрытая ссылка на другой объект — его **прототип** (внутреннее свойство \[\[Prototype\]\]).

Когда ты обращаешься к свойству/методу объекта:

1. JS сначала ищет его в самом объекте.

2. Если не нашёл — идёт в прототип.

3. Если и там нет — в прототип прототипа.

4. И так далее, пока не дойдёт до null.

Это называется **прототипной цепочкой** (prototype chain).

```javascript
const animal = {
  eats: true,
  walk() {
    console.log("Животное идёт");
  }
};

const rabbit = {
  jumps: true
};

// Устанавливаем прототип
Object.setPrototypeOf(rabbit, animal);

rabbit.walk(); // "Животное идёт"  ← нашёл в прототипе
console.log(rabbit.eats); // true
```

### Где и в каких механизмах используются прототипы

- Наследование - Основной способ наследования в JS `Object.create(), `__`proto`__`, Object.setPrototypeOf`
- Конструкторы \+ .prototype - Классический паттерн до появления class `function User() {} + User.prototype.sayHi = ...`
- Классы (class) - Синтаксический сахар над прототипами `class User extends Person`
- Встроенные объекты - Все методы массивов, строк, чисел и т.д. лежат на прототипах `Array.prototype.map, String.prototype.slice`
- Общие методы - Чтобы не копировать методы в каждый экземпляр (экономия памяти) (Методы на prototype)
- Object.create() - Чистое прототипное наследование без конструктора `const child = Object.create(parent)`
- Проверка цепочки (instanceof, isPrototypeOf, Object.getPrototypeOf) `rabbit instanceof Object`

### Важные моменты

1. **\__proto_\_ vs prototype**

   * \__proto_\_ — это ссылка на прототип **у экземпляра** (геттер/сеттер).

   * .prototype — свойство **у функции-конструктора**, которое станет прототипом создаваемых объектов.

2. **Классы — это сахар**

   ```javascript
   class User {
     sayHi() { console.log("Hi"); }
   }
   // Под капотом примерно так:
   // User.prototype.sayHi = function() { ... }
   ```

3. **Зачем вообще прототипы?**

   * Экономия памяти (методы лежат в одном месте).

   * Динамическое наследование (можно менять прототип на лету).

   * Гибкость (можно делать миксины, изменять поведение встроенных объектов и т.д.).

4. **Современные рекомендации**

   * Лучше использовать class \+ extends.

   * Для чистого прототипного стиля — Object.create().

   * Избегать прямого изменения \__proto_\_ (медленно и считается устаревшим).

   * Не рекомендуется менять прототипы встроенных объектов (Array.prototype и т.д.) в продакшене.
