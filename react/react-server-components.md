# React Server Components

### Что такое React Server Components?

React Server Components — это компоненты, которые рендерятся исключительно на сервере и не включаются в клиентский JavaScript-бандл. Они позволяют выполнять тяжелые вычисления и доступ к данным (например, к базе данных или файловой системе) на сервере, отправляя на клиент только готовый HTML или минимальный JavaScript для интерактивности.

Основные особенности:

-   **Рендеринг только на сервере**: Server Components не загружают JavaScript на клиент, уменьшая размер бандла.

-   **Прямой доступ к серверным ресурсам**: Компоненты могут напрямую обращаться к базе данных, API или другим серверным ресурсам без необходимости создания отдельных эндпоинтов.

-   **Нулевая интерактивность**: Server Components статичны и не содержат клиентской логики (например, обработчиков событий или хуков вроде useState, useEffect).

-   **Интеграция с клиентскими компонентами**: Server Components могут рендерить клиентские компоненты, помеченные директивой "use client".

### Отличия от клиентских компонентов и SSR

1.  **Клиентские компоненты**:

    -   Рендерятся в браузере.

    -   Содержат интерактивную логику (хуки, обработчики событий).

    -   Полностью загружают JavaScript на клиент.

2.  **Server-Side Rendering (SSR)**:

    -   Рендерит HTML на сервере, но весь JavaScript для компонентов отправляется на клиент для "гидрации" (восстановления интерактивности).

    -   Требует загрузки всего бандла на клиент, что может быть ресурсоемким.

3.  **React Server Components**:

    -   Рендерятся только на сервере, без отправки JavaScript для этих компонентов на клиент.

    -   Не требуют гидрации для самих Server Components.

    -   Могут передавать данные или рендерить клиентские компоненты для интерактивных частей UI.

### Преимущества React Server Components

1.  **Уменьшение размера бандла**:

    -   Поскольку Server Components не отправляют JavaScript на клиент, размер загружаемого кода значительно сокращается.
2.  **Оптимизация загрузки данных**:

    -   Server Components могут напрямую запрашивать данные на сервере, минимизируя количество сетевых запросов между клиентом и сервером.
3.  **Упрощение архитектуры**:

    -   Нет необходимости создавать отдельные API-эндпоинты для получения данных, так как Server Components могут обращаться к серверным ресурсам напрямую.
4.  **Улучшение производительности**:

    -   Тяжелые вычисления (например, обработка данных или генерация сложных UI) выполняются на сервере, снижая нагрузку на клиент.
5.  **Поддержка потокового рендеринга**:

    -   RSC интегрируются с Suspense, позволяя рендерить части страницы по мере готовности данных.

### Ограничения

1.  **Отсутствие интерактивности**:

    -   Server Components не могут содержать хуки (useState, useEffect) или обработчики событий, так как они не выполняются на клиенте.
2.  **Требуется серверная инфраструктура**:

    -   Для использования RSC нужен сервер, поддерживающий их рендеринг (например, Next.js 13+ с App Router).
3.  **Сложность интеграции**:

    -   Необходимо разделять логику между серверными и клиентскими компонентами, что может усложнить архитектуру для начинающих разработчиков.
4.  **Ограниченная поддержка**:

    -   На данный момент RSC полностью поддерживаются только в фреймворках вроде Next.js (на октябрь 2025 года).

### Пример использования

Допустим, у вас есть компонент, отображающий список постов из базы данных:

**Серверный компонент, который запрашивает данные из базы и рендерит статический HTML.**

```javascript
// Posts.server.js (Server Component)
import db from './database';

async function Posts() {
  const posts = await db.getPosts(); // Прямой доступ к базе данных
  return (
    <div>
      <h1>Posts</h1>
      <ul>
        {posts.map(post => (
          <li key={post.id}>{post.title}</li>
        ))}
      </ul>
      <ClientComponent /> {/* Встраивание клиентского компонента */}
    </div>
  );
}

export default Posts;
```

**Клиентский компонент, который добавляет интерактивность (например, счетчик кликов).**

```javascript
// ClientComponent.client.js (Client Component)
"use client";

import { useState } from 'react';

export default function ClientComponent() {
  const [count, setCount] = useState(0);
  return (
    <button onClick={() => setCount(count + 1)}>
      Clicked {count} times
    </button>
  );
}
```

### Как использовать RSC в проекте?

1.  **Выберите подходящий фреймворк**:

    -   RSC лучше всего работают с Next.js (App Router, начиная с версии 13). Другие фреймворки могут иметь ограниченную поддержку.
2.  **Разделите компоненты**:

    -   Используйте директиву "use client" для компонентов, которые должны рендериться на клиенте.

    -   Оставляйте неинтерактивные компоненты как серверные.

3.  **Настройте Suspense**:

    -   Используйте `<Suspense>` для управления асинхронным рендерингом и отображения загрузочных состояний.

### Сценарии использования

-   **Статические страницы**: Отображение контента, который не требует интерактивности (например, блоговые посты, документация).

-   **Оптимизация загрузки данных**: Запросы к базе данных или тяжелым API, выполняемые на сервере.

-   **Потоковый рендеринг**: Постепенная загрузка частей страницы (например, в интернет-магазинах).
